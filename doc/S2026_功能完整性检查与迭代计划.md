# 功能完整性检查与迭代计划

**文档编号**：`S2026_功能完整性检查与迭代计划.md`  
**适用范围**：对照产品信息架构与设计文档，梳理「申报 · 问卷 · 系统」各业务链路是否形成**可演示、可交付用户价值**的闭环；**不包含**部署安全、渗透测试等运维向清单（另案处理）。

**对标依据**：`doc/base.md`、`doc/project-declaration-config-design.md`、`README.md`（角色与模块）、`doc/项目状态_申请审核状态梳理.md`（状态语义）。

---

## 一、结论摘要

| 域 | 总体完整度 | 说明 |
|----|------------|------|
| 申报核心链路（项目→配置→填材料→审批） | **较高** | 列表、表单、审批中心与画布配置均已落地；部分页面仍为占位或「最小可用」。 |
| 配置驱动申报（与设计文档的理想模型） | **中等** | 可视化配置与渲染器已存在，与设计文档中的句式模板、附件约束全覆盖等仍有差距。 |
| 审批流产品化（相对 BPMN 画布） | **中等** | 审批/并行/角色指派等主路径可用；画布中多项「增强节点」仅为占位说明，引擎未实现。 |
| 问卷模块 | **较高** | 设计、匿名填写、数据页已接入路由；与申报模块的数据打通视业务是否需要单独规划。 |
| 系统管理 | **较高** | 用户、权限、字典、设置齐全；**独立「菜单管理」后台**未体现（侧栏由前端静态配置 + 权限码过滤）。 |
| 体验增强（base.md） | **低** | 「配置复用」已有复制版本；**批量导入用户**已实现（CSV）；**AI 辅助**未纳入实现。 |
| 工作台数据呈现 | **低** | 首页统计卡片为占位数据，未对接真实汇总接口。 |

## 二、按模块的功能完整性矩阵

### 2.1 申报（`/declaration/*`）

| 能力 | 预期（对标文档） | 现状 | 缺口 / 迭代建议 |
|------|------------------|------|-----------------|
| 首页工作台 | 关键数量一览 | `Dashboard` 中项目数、申报数、待审批、用户数均为 **0 占位** | 对接统计接口或聚合现有列表接口计算；按角色展示不同卡片 |
| 我的资料 | 与档案、证件、学历等一致的可维护个人库 | 已实现多区块页面与档案文件接口 | 对照人事口径核对字段是否齐全；缺失项列入表单与字典 |
| 项目管理 | 创建/发布/关闭全生命周期 | 已有列表与状态（见状态梳理文档） | 若有「复制项目」「从历史项目继承配置」需求，单独立项 |
| 申报配置 | 项目级信息结构 + 材料结构 + 版本发布 | `ProjectDeclarationConfig`、可视化编辑器、复制新建版本 | 与设计文档 **§10** 对齐：配置校验规则、导入导出 JSON/YAML、子模块附件 `maxSize/templateUrl` 等是否在渲染层全部生效需逐项验收 |
| 我的申报 | 草稿、提交、进度感知 | `MaterialList` / `MaterialForm`、提交与 PDF 预览 | 撤回已提交（若业务需要）、截止期提醒等未在表中体现则列为可选 |
| 审批中心 | 待办、已办、筛选 | `ApprovalCenterPage`、`ApprovalProcessPage` | 与「增强审批节点」未实现部分区分：当前满足人工审批主路径即可视为 V1 完整 |
| 审批流设计 | 多人并行、部门/专家角色 | 画布可编辑；后端会签与并行轨有据可查 | 画布里 **抄送、子流程、自动节点、定时、条件网关执行** 等为「规划中」，属功能缺口，需单独排期 |
| 模板管理 | 业务 Word/PDF 等模板 | `TemplateList` 为 **服务器端模板文件上传列表**，与申报配置里的字段模板不同概念 | 产品文案上区分「附件模板文件」与「申报书模板」；避免用户误解 |

### 2.2 问卷（`/survey/*`）

| 能力 | 预期 | 现状 | 缺口 / 迭代建议 |
|------|------|------|-----------------|
| 问卷概览 | 总览入口 | `SurveyHome` | 是否需统计图表、快捷入口到「最近模板」，按运营需求增强 |
| 问卷设计 | 拖拽/发布版本 | `SurveyDesignList`、`SurveyDesign` | 复杂逻辑（跳转、配额）若未实现，列入下一版 |
| 匿名填写 | 公开链接可填 | 独立路由 `SurveyFill` | 填前说明、提交成功页品牌化等体验项 |
| 数据采集与导出 | 导出填写结果 | `SurveyExport` | 字段级匿名脱敏、按模板维度权限是否与 RBAC 一致需业务确认 |

### 2.3 系统（`/system/*`）

| 能力 | 预期（base.md） | 现状 | 缺口 / 迭代建议 |
|------|-----------------|------|-----------------|
| 用户管理 | 创建用户、**批量导入** | `UserList` 支持 CSV 批量、`/users/bulk` | Excel 模板下载、失败行重试可优化 |
| 角色 / 权限 | 角色与菜单可达 | 权限目录、角色授权编辑 | **动态菜单库**：若产品要求运营可配菜单项而不改代码，需新增数据模型与页面（当前为 `navigation.tsx` 静态配置） |
| 系统设置 / 字典 | 可维护选项集 | `SystemSettings`、`DictMaintenance` | 与申报表单选项联动回归测试纳入迭代验收 |
| README 中的专家角色 | `expert` 专家评审 | 流程画布支持 `role_expert`，RBAC 含专家权限包 | 确认专家审批队列与教师/管理员列表筛选是否覆盖所有申报场景 |

## 三、与设计文档《申报项目配置设计》的差异（功能视角）

以下条目用于**验收配置驱动能力是否「完整覆盖设计」**，而非代码优劣评判。

1. **句式模板（sentenceTemplate）**：设计文档中 Map 类型支持占位符拼句；需在配置 schema 与 `DeclarationConfigRenderer` 中确认是否已实现及保存回读一致。  
2. **List 行数、列校验**：`maxRows`、单元格类型与附件列是否在保存与提交时统一校验。  
3. **附件定义**：`accept`、`maxSize`、`templateUrl`（下载模板）是否在渲染侧全部 enforced，并与后端存储一致。  
4. **版本与历史数据**：升版后旧材料实例的兼容策略是否在界面或说明中有体现（仅管理员可见提示亦可）。  
5. **导出/打印**：设计文档提及按模块聚合导出；当前已有材料 PDF 合并预览，是否满足「正式打印包」需产品确认。

## 四、迭代计划（按功能优先级）

### 第一阶段：闭环可用（对外演示 / 校内试点）

**目标**：用户从登录到「填资料—报项目—审完」无断点；首页数据真实。

| 序号 | 事项 | 验收标准 |
|------|------|----------|
| F1 | 工作台统计接入真实数据 | 至少：项目数（教师可见范围）、我的材料数、待我审批数；管理员可加用户数 |
| F2 | 申报主路径回归清单 | 固定测试账号跑通：发布项目 → 配置发布 → 教师提交 → 多级审批通过或驳回 |
| F3 | 模板管理文案与导航 | 菜单名称与页面说明区分「附件类模板文件」与申报配置，避免误解 |
| F4 | 审批流文档化（对内） | 明确：画布中哪些节点已接入执行引擎，哪些仅为 UI 占位（与 `ApprovalFlowNodePalette` 一致） |

### 第二阶段：配置驱动与设计文档对齐

| 序号 | 事项 | 验收标准 |
|------|------|----------|
| F5 | 配置项与设计文档 §4 对照表 | 每项 schema 字段有「已实现 / 部分 / 未实现」标注；未实现项进入 backlog |
| F6 | 配置复制与跨项目复用 | 已有「复制新建版本」；如需「从其他项目导入配置」，补充交互与接口 |
| F7 | 导出能力对齐预期 | 确定 V1：PDF 合并是否足够；若需 Word/附件打包，立项专项 |

### 第三阶段：审批流增强（按业务价值排序）

| 序号 | 事项 | 说明 |
|------|------|------|
| F8 | 条件分支 / 排他网关 | 画布提示「规划中」，需后端执行语义与前端保存结构一并设计 |
| F9 | 抄送、催办、超时 | 通常依赖消息通道；无通道时可先做站内记录或日志 |
| F10 | 自动节点（接口/消息） | 与外部系统对接时实施 |

### 第四阶段：体验与运营（base.md 中的增量）

| 序号 | 事项 | 说明 |
|------|------|------|
| F11 | 动态菜单（可选） | 若客户要求「不改代码换菜单」，落地菜单 CRUD 与权限绑定 |
| F12 | AI 辅助（可选） | 单独需求说明书；与本迭代计划解耦 |
| F13 | 问卷与申报联动（可选） | 例如问卷结果回填档案字段；视业务是否真实需要 |

## 五、使用方式建议

- **迭代会议**：从第四节表格按阶段勾选；每条保留「负责人 / 预计版本号」。  
- **功能测试**：以第二节矩阵为检查表，每列「缺口」关闭后更新矩阵一行。  
- **与设计评审**：第三节作为配置模块专题评审提纲。
