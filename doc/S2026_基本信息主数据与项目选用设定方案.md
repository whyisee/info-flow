# 基本信息主数据 · 项目字段选用 · 打印格式 — 设定方案

**文档编号**：与本仓库 `doc/S2026_*.md` 系列一致，便于版本并列管理。  
**目的**：把「人事档案式基本信息」与「某次申报在表格上长什么样」解耦：前者尽量**全、稳、与版式无关**；项目侧只做**从主数据目录中挑选**与**打印/套打已配置好的版式**；**不在主数据层按项目维护多种日期/表格格式**。

**关联文档**：`doc/project-declaration-config-design.md`（项目级配置与模块/子模块）；实现上可与 `declaration_basic` 等模块及 `profileModuleFields.ts` 中的键名逐步对齐。

---

## 1. 问题与原则

### 1.1 要解决的问题

- 不同行政表格对「同一名称」的**展示格式、行列布局、是否必填**不同，若都堆在「用户基本信息」里，会导致主数据与版式纠缠、无法复用。
- 若要求每个项目单独维护一套「基本信息」内容，又会产生数据重复、口径不一。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **主数据与版式分离** | 用户侧只维护**语义内容**（值与附件引用）；**纸面/ PDF 上怎么排、日期用点还是斜杠**归打印模板与申报配置，不归入主数据字段定义。 |
| **单一真源** | 同一语义（如身份证号、最高学历）在用户档案中仅存一处；项目不能复制一套平行字段存另一份「副本」，除非业务明确要求「申报快照」归档（见 §6）。 |
| **项目只做选用与约束** | 创建/编辑申报项目配置时，从**全局字段目录**勾选本项目需要的字段，并设定必填、排序、分组展示名（可与目录默认标签不同）；**不为主数据增加「按项目的格式类型」**。 |
| **打印格式单独维护** | 套打、导出 PDF 使用项目已配置的模板（字段占位映射到语义键）；模板迭代不影响主数据存储结构。 |

---

## 2. 概念模型

### 2.1 三层对象

```
全局基本信息字段目录（Field Catalog）
        ↑ 选用（子集 + 约束）
申报项目 — 「基本信息段」配置（Project Profile Binding）
        ↑ 映射
打印 / 导出模板（已有版式：格子、样式、日期格式）
```

- **字段目录**：系统级清单，描述有哪些「可选用」的内容字段（键、类型、默认标签、校验 hint、所属模块如 basic/contact）。**不包含**某省表格第几格。
- **项目基本信息段**：某项目声明「本项目采集目录中的哪些键」，以及在本项目内是否必填、展示顺序、分组标题。**格式的视觉差异**交给打印模板。
- **打印模板**：将语义键绑定到版式（单元格、段落、图片槽）；**YYYY.MM、中文年月日**等仅在导出层生成。

### 2.2 数据归属

| 数据类型 | 存放位置（逻辑） |
|----------|------------------|
| 用户填写的基本内容、档案附件 | 用户档案/个人资料（与现网 `declaration_basic` 等模块一致，按模块分块存也可） |
| 本项目要哪些基本字段、是否必填 | 项目配置中的「基本信息段」 |
| 导出长什么样 | 项目关联的打印模板或导出配置（可与现有「模板管理」「PDF 生成」衔接） |

## 3. 全局字段目录（应尽量完善）

### 3.1 目录条目内容

每一条目录项至少包含：

- **语义键（stable key）**：全局唯一，持久化与接口使用该键（例：`birth_date`、`highest_edu_level`）。新增字段优先在此登记。
- **数据类型**：文本、日期、枚举（关联字典）、附件引用、多行文本等。
- **默认标签**：表单默认文案；项目可选用别名覆盖展示。
- **可选校验**：最大长度、正则、枚举码表引用（仅约束「填什么」，不约束「纸上写成哪种字符串」）。
- **归属模块**：便于 UI 分 Tab（如基本信息 / 联系方式 / 导师关系）；与现有拆分一致可降低改动成本。

**维护方式**：目标由管理员在 **「基本信息字段配置」** 页面维护（见 §8），不再依赖仅开发者改代码。

### 3.2 与现有实现的关系

当前前端已对若干键做了模块划分（参见 `profileModuleFields.ts` 中 `BASIC_KEYS`、`CONTACT_KEYS` 等）。**目录应以代码中的键为基准逐步补齐**，缺失的业务字段（如工作经历列表）在目录中单独立项并在档案结构中扩展存储。

### 3.3 刻意不包含的内容

- 不包含「附件 3 第 5 行」「东油表第三列」等版式信息。
- 不包含「本项目日期必须为 `YYYY.MM`」——该类需求在 **导出规则或模板映射** 中实现。

## 4. 项目配置：从目录中挑选

### 4.1 配置单元建议结构（逻辑）

对单个申报项目（或其申报配置版本）增加一段：

- **基本信息段启用**：布尔（也可默认启用）。
- **选用字段列表**：有序数组，每项包含：
  - `field_key`：指向目录中的语义键；
  - `required_in_project`：在本项目是否必填（可严于目录默认值）；
  - `visible_label`：可选，覆盖默认标签；
  - `group`：可选，用于申报向导上的分组标题（如「学历学位」「现单位信息」）。
- **不包含**：日期格式串、表格行列坐标（属于打印层）。

### 4.2 填报体验

- 教师打开「我的资料」或进入项目填报时：**若存在项目上下文**，则按该项目选用字段渲染子集并标注必填；未选用的目录字段在该申报路径下可不展示（档案里仍可保留历史值）。
- **无项目上下文**（纯维护档案）：可展示**目录全量或按模块全量**，便于一次性填齐。

### 4.3 校验策略

- **档案保存**：对已填写内容按目录类型做通用校验。
- **提交本项目材料**：除通用校验外，叠加「本项目选用字段」的必填校验。

---

## 5. 打印格式（已配置版式）

- 打印/PDF 模板使用**同一套语义键**作为数据源；模板内定义：
  - 位置与样式；
  - **展示格式化函数**（如日期 → `YYYY.MM`、→ `YYYY年MM月`），仅影响导出字符串，**不回写主数据**。
- 多个官方表格对应多套模板；同一用户档案可被多套模板消费。

---

## 6. 申报快照（可选增强）

若法规要求「提交当时版本的表格影像固化」：

- 在材料提交成功时生成**当时申报配置版本 + 当时档案字段子集**的只读快照（JSON 或归档 PDF），与审批记录关联。
- 主数据仍可后续修正用于新项目；历史材料以快照为准。

---

## 7. 演进与治理

| 事项 | 做法 |
|------|------|
| 新增业务字段 | 先入库全局目录 → 再在某项目选用中出现 |
| 字段改名 | 目录改默认标签；旧键保留兼容或做迁移脚本 |
| 目录膨胀 | 按模块、标签分类；可选「高级字段」折叠展示 |

## 8. 基本信息字段配置页（管理员）

**现状**：教师端「基本信息」等页面的表单项在代码中**写死**（如 `profileModuleFields.ts` 与页面 JSX 绑定的键集合），新增业务字段需改代码、发版。  
**目标**：提供**系统管理侧**的「基本信息字段目录」配置能力，由授权管理员增删改字段元数据；教师端表单从**目录（接口下发）动态渲染**，与 §3～§4 的「全局目录 + 项目选用」闭环一致。

### 8.1 功能范围

| 能力 | 说明 |
|------|------|
| **浏览目录** | 分页或按「归属模块」分组的字段列表；支持按语义键、标签关键字筛选。 |
| **新增字段** | 录入一条新的目录项，写入后即刻出现在**项目选用候选集**与（策略见下）教师档案表单。 |
| **编辑字段** | 修改标签、说明、类型展示参数、校验、字典引用、排序、是否启用等。**语义键**原则上创建后不可改；若必须改名，走「废弃键 + 新键 + 数据迁移」流程（见 §8.5）。 |
| **停用 / 删除** | **停用**：不再出现在新项目选用列表，已选用项目可提示「引用已停用字段」；历史档案 JSON 仍保留该键数据。**硬删除**：仅当无任何项目选用且无档案数据引用时允许，或仅供实施人员后台操作。 |
| **排序与分组** | 目录内 `sort_order`、`module_code`（或分组键），影响教师端默认 Tab/区块内字段顺序。 |
| **引用关系提示（可选）** | 编辑页展示：已有 N 个申报配置版本选用该字段，避免误删。 |

### 8.2 单条「字段目录」可编辑属性（建议）

下列与 §3.1 对齐，并补充运行时可改项：

| 属性 | 说明 |
|------|------|
| `field_key` | 新建时必填，建议 `snake_case`，唯一；创建后界面只读。 |
| `data_type` | 如：`text` / `textarea` / `number` / `date` / `select` / `multi_select` / `upload` / `image` 等。 |
| `default_label` | 表单标签默认文案。 |
| `placeholder` | 选填。 |
| `help_text` | 字段下方说明；可支持简单换行。 |
| `module_code` | 归属模块（与现有 basic / task / contact / supervisor 等对齐，或扩展新模块码）。 |
| `dict_type_code` | 若为枚举类，绑定系统字典类型编码（与「字典维护」模块一致）。 |
| `validation` | JSON 或结构化表单：必填默认值、`max_length`、`pattern`、数值范围等（**不包含纸面格式**，见 §3.3）。 |
| `sort_order` | 同模块内排序。 |
| `enabled` | 是否可选用于新项目。 |
| `storage_hint` | 可选：`scalar`（存在模块扁平 JSON）、`attachment_id`、`json_blob` 等，供后端与导出约定存储位置（实现期细化）。 |

### 8.3 权限与入口

- **权限码建议**：单独设立如 `system:profile-field:manage`（或与「系统设置」同级的高级配置权限），仅 `school_admin` 或具备该权的账号可见菜单 **系统 → 基本信息字段**（名称可微调）。
- **审计**：新增、修改、停用字段记录操作人、时间（与现有系统管理习惯一致即可）。

### 8.4 页面交互要点

1. **列表页**：表格列展示键、标签、模块、类型、启用状态、排序；行操作「编辑」「停用」。  
2. **新建 / 编辑抽屉或独立页**：表单分区「标识与类型」「展示与帮助」「校验与字典」「模块与排序」。  
3. **键名校验**：实时校验唯一性与命名规范；禁止空格与非法字符。  
4. **保存后**：若接入了缓存，需失效「字段目录」缓存，避免教师端长期读到旧列表。

### 8.5 语义键变更策略（强调）

- **推荐**：目录只改 `default_label`、帮助文案、校验强度，**不改** `field_key`。  
- **必须改名时**：新增新键目录项 → 数据迁移任务（把档案 JSON 中旧键拷到新键）→ 项目选用配置批量替换 → 打印模板映射更新 → 下线旧键。不作为常规按钮提供。

### 8.6 与教师端、种子数据的关系

| 阶段 | 行为 |
|------|------|
| **初部署** | 用迁移脚本或种子数据，将当前 `profileModuleFields.ts` 中的键批量写入「字段目录」表，保证与线上一致。 |
| **切换动态表单** | 教师「我的资料」页改为：`GET /api/.../profile-field-catalog`（仅启用的字段）+ 动态表单组件；硬编码表单项逐步删除。 |
| **项目选用配置** | 项目配置里勾选字段时，下拉数据来自**同一目录接口**（可含已停用字段仅用于展示历史，视产品决定）。 |

### 8.7 本页验收要点

1. 管理员新增一条目录字段后，无需发版即可在「项目申报配置 — 基本信息段」中被选用（若启用）。  
2. 停用字段后，新项目配置不可再选；旧数据仍可查看或按策略提示。  
3. 教师端表单与目录一致：展示的标签、类型、字典选项与配置页修改同步（在合理缓存策略下）。

---

## 9. 验收要点（本设定整体落地时）

1. 任意两个申报项目可选用完全不同的基本信息字段子集，而用户档案键空间统一。  
2. 同一 `birth_date` 在主数据仅存一种日期语义；不同 PDF 出口可有不同字符串样式。  
3. 项目配置界面可理解为：**勾选字段 + 必填 + 排序 + 分组**，而非「再录一套基本信息」。  
4. 打印层仅依赖「模板 + 语义键」，不反向要求主数据拆多套格式字段。  
5. **管理员可通过「基本信息字段配置」维护目录**，教师端基于目录动态展示，摆脱页面写死表单项。
