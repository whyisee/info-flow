# S2026 教师端使用体验问题与需求建议

## 1. 背景

从教师端使用者视角看，系统的核心任务不是“配置申报”，而是在有限时间内准确完成材料填报、减少重复输入、避免格式返工，并清楚知道材料当前处于什么状态。教师通常不会长期停留在系统里学习复杂操作，而是在收到申报通知后集中使用几次，因此教师端体验更依赖清晰入口、强引导、自动保存、错误提示和可预览的最终成果。

本文从教师实际使用路径出发，梳理可能发现的问题，并提出可落地的需求建议。

## 2. 教师端典型使用路径

1. 收到申报通知，进入系统查看可申报项目。
2. 选择项目，阅读申报条件、截止时间和材料要求。
3. 维护或确认个人基本信息。
4. 填写申报表各模块内容。
5. 上传佐证材料。
6. 预览打印申报表，检查格式和内容。
7. 提交申报材料。
8. 查看审核进度，按退回意见修改。
9. 申报结束后下载归档材料。

## 3. 可能发现的问题

### 3.1 项目入口和申报状态不够直观

教师进入系统后最关心的是“我现在能申报什么”“截止到什么时候”“我是否已经提交”。如果项目列表只展示项目名称和基础状态，教师需要点进多个页面才能确认自己是否符合条件、是否已填写、是否临近截止。

典型问题：

- 可申报项目、已提交项目、已截止项目没有明显分组。
- 截止时间、剩余天数、当前审核状态不够醒目。
- 不清楚项目是否需要先完善基本信息。
- 不清楚材料是否还有未完成项。

### 3.2 基本信息重复维护成本高

教师的基本信息通常在多个项目之间复用，但不同项目又会选择不同字段。如果系统没有清晰区分“个人主档信息”和“本项目申报信息”，教师会困惑哪些信息是全局更新、哪些只影响当前项目。

典型问题：

- 历史项目填过的信息不能自动带入。
- 下拉字典、单位、职称、学历等字段如果没有反显或默认值，会造成重复录入。
- 修改基本信息时，不知道是否会影响已提交材料。
- 附件类基本信息，例如身份证明、学历证明、职称证明，可能需要反复上传。

### 3.3 表单模块较多时缺少进度感

申报表往往很长，包含基本信息、工作经历、业绩成果、奖项、论文、承诺签章等多个部分。教师填写时需要知道还有多少没完成、哪些是必填、哪里有错误。

典型问题：

- 右侧目录只用于跳转，没有完成状态。
- 必填项缺失只在提交时统一报错，返工成本高。
- 保存后没有明确提示“已保存到服务器”。
- 长表单滚动后容易迷失当前所在模块。

### 3.4 表格型内容录入效率不高

工作经历、奖项、项目、论文等内容本质上是表格数据。如果只能用普通表单逐条新增，教师会觉得效率低，尤其是有多年历史成果需要录入时。

典型问题：

- 新增多条经历或成果需要重复点击。
- 不支持复制上一行。
- 不支持 Excel 粘贴或批量导入。
- 行内字段太多时，横向或纵向排布不清楚。
- 表格列标题和最终打印样式不一致，教师不知道最终输出效果。

### 3.5 附件上传和材料关联不够清楚

教师上传附件时，需要知道“哪些材料必须上传”“上传后关联到哪个成果或字段”“文件是否符合大小和格式要求”。如果附件只是一个统一上传区，后续审核人员也难以定位。

典型问题：

- 附件要求分散在说明文字里，不够结构化。
- 上传失败原因不明确。
- 不支持拖拽上传、批量上传、替换文件。
- 不支持把附件关联到某一条业绩、论文或奖项。
- 文件名不规范时没有自动命名建议。

### 3.6 打印预览和实际导出可能不一致

教师提交前通常会关注最终申报表是否美观、内容是否截断、表格是否跨页合理。如果系统只提供普通页面预览，教师无法确信导出的正式表是否符合要求。

典型问题：

- 页面展示和打印 PDF 不一致。
- 长文本是否换行、表格是否分页不明确。
- 图片、签章、附件清单是否出现在最终文件中不清楚。
- 预览错误无法直接定位回对应字段。

### 3.7 保存、提交、退回修改的状态边界不清晰

教师需要明确理解“暂存”“提交”“退回”“重新提交”的差异。如果状态变化不明显，容易出现以为提交了但实际只是保存、以为可以修改但状态已锁定的情况。

典型问题：

- 暂存和提交按钮视觉层级不明显。
- 提交后哪些内容不能改不明确。
- 退回意见分散在审核记录里，不知道要改哪里。
- 重新提交后缺少提交时间和版本记录。

### 3.8 缺少面向教师的帮助和示例

复杂申报项目里，教师往往需要示例文本、填报口径和常见问题。如果帮助内容只存在于通知文件中，填报时需要频繁切换窗口。

典型问题：

- 字段旁缺少填报说明。
- 大文本类字段缺少示例和字数提示。
- 不同人才类别或学科类别的口径不清楚。
- 缺少常见退回原因提示。

### 3.9 移动端或小屏体验可能不足

教师可能在手机或平板上查看状态、补充简单信息、上传照片。如果页面只适配桌面宽屏，移动端会出现表格难操作、按钮难点击、文本溢出等问题。

典型问题：

- 长表格在手机上横向滚动困难。
- 上传附件在移动端体验差。
- 右侧目录、固定工具栏占用过多空间。
- 弹窗表单在小屏中高度过高。

### 3.10 通知提醒不足

教师不一定每天登录系统。如果缺少消息提醒，容易错过截止时间、退回修改、审核通过等关键节点。

典型问题：

- 项目开放、临近截止、退回修改没有站内提醒。
- 邮件、短信、企业微信等外部通知缺失。
- 通知里没有直接跳转到待处理材料。

## 4. 建议需求

### 4.1 教师端工作台

建设教师个人工作台，作为教师登录后的默认首页。

建议内容：

- 可申报项目卡片：项目名称、截止时间、剩余天数、当前状态。
- 我的申报进度：未开始、填写中、已提交、审核中、已退回、已通过。
- 待办事项：待完善基本信息、待上传附件、待修改退回意见。
- 最近操作：最近保存时间、最近提交时间。
- 快捷入口：继续填报、查看预览、下载申报表。

优先级：P0。

### 4.2 申报进度和完整性检查

在申报表页面增加实时进度和完整性检查。

建议内容：

- 模块目录展示完成状态。
- 必填字段缺失实时提示。
- 附件缺失提示。
- 字数超限、格式错误、日期范围错误即时校验。
- 提交前展示完整性检查清单，并支持点击定位。

优先级：P0。

### 4.3 自动保存和版本恢复

降低教师因误关闭、网络波动、长时间填写导致的数据丢失风险。

建议内容：

- 表单变更后自动保存草稿。
- 页面顶部展示“已保存 / 保存中 / 保存失败”状态。
- 保存失败时保留本地缓存。
- 支持查看最近草稿版本，必要时恢复。
- 提交后生成申报快照，退回修改形成新版本。

优先级：P0。

### 4.4 基本信息复用和变更确认

优化个人主档信息和项目申报信息之间的关系。

建议内容：

- 教师端展示“来自个人主档”的字段来源标识。
- 项目申报表自动带入个人主档信息。
- 修改主档信息时提示影响范围。
- 支持从历史申报复制基本信息和常用成果。
- 支持常用证明附件复用。

优先级：P0。

### 4.5 表格型内容的高效录入

针对工作经历、项目经历、奖项、论文等模块提供表格化操作。

建议内容：

- 行内编辑。
- 新增行、复制行、删除行、拖拽排序。
- 支持从 Excel 粘贴多行数据。
- 支持导入模板 Excel。
- 支持批量校验日期、必填、字数。
- 支持一键生成序号。

优先级：P1。

### 4.6 附件中心和字段级关联

把附件从“上传文件”升级为“材料证据管理”。

建议内容：

- 每个申报项目有独立附件中心。
- 附件可关联到字段、表格行或模块。
- 显示附件要求：格式、大小、是否必传、命名规则。
- 支持批量上传、拖拽上传、替换文件。
- 上传后自动计算文件数量和缺失项。
- 支持常用附件复用，但复制到当前项目形成独立快照。

优先级：P1。

### 4.7 所见即所得打印预览

让教师在提交前看到接近最终归档文件的效果。

建议内容：

- 提供 A4 分页预览。
- 支持 PDF 预览和下载。
- 预览中标记截断、跨页异常、空白必填项。
- 点击预览中的异常区域可以回到对应字段。
- 提交前固定生成一份预览快照。

优先级：P1。

### 4.8 退回意见定位和修改清单

让退回修改从“读审核意见”变成“按清单处理”。

建议内容：

- 审核意见按模块、字段、附件关联。
- 教师端展示退回修改清单。
- 每条意见支持点击定位。
- 修改后可标记“已处理”。
- 重新提交时展示本次修改摘要。

优先级：P1。

### 4.9 填报说明、示例和智能辅助

把填报说明嵌入到具体字段和模块中。

建议内容：

- 字段级说明和示例。
- 大文本字段展示字数限制和推荐结构。
- 不同类别展示不同填报口径。
- 常见问题入口。
- 根据已填内容提示可能缺失的佐证材料。

优先级：P2。

### 4.10 多渠道通知提醒

提升教师对关键节点的感知。

建议内容：

- 站内消息：项目开放、截止提醒、退回修改、审核通过。
- 临近截止提醒：例如截止前 7 天、3 天、1 天。
- 邮件或企业微信通知。
- 通知可直接跳转到对应申报材料。
- 教师可查看通知已读状态。

优先级：P2。

### 4.11 移动端轻量体验

移动端不一定承载完整填报，但应支持查看和轻量处理。

建议内容：

- 移动端工作台。
- 查看申报状态和审核意见。
- 上传或替换附件。
- 简单字段补充。
- 下载或预览 PDF。

优先级：P2。

## 5. 页面优化建议

### 5.1 教师首页

建议将教师首页从普通菜单页调整为任务型工作台。

页面结构：

- 顶部：当前可申报项目、待办数量、最近截止项目。
- 中部：我的申报卡片列表。
- 右侧或底部：通知、帮助、常用附件。

### 5.2 申报填报页

建议采用“左侧目录 + 中间表单 + 右侧检查清单”的布局。

关键优化：

- 左侧目录显示完成状态和错误数量。
- 中间表单聚焦录入。
- 右侧检查清单显示待处理项。
- 顶部固定保存状态、预览、提交按钮。

### 5.3 附件上传页

建议附件不要只做成文件列表，而是按材料要求组织。

页面结构：

- 必传附件区。
- 按模块关联附件区。
- 其他补充材料区。
- 上传记录和替换记录。

### 5.4 打印预览页

建议打印预览作为提交前必经检查步骤。

页面结构：

- 左侧页面缩略图。
- 中间 A4 预览。
- 右侧异常列表。
- 顶部下载 PDF、返回修改、确认提交。

## 6. 数据与状态设计建议

### 6.1 申报材料状态

建议教师端明确展示以下状态：

| 状态 | 含义 | 教师是否可编辑 |
| --- | --- | --- |
| not_started | 未开始 | 是 |
| draft | 草稿 | 是 |
| submitted | 已提交 | 否 |
| returned | 已退回 | 是 |
| resubmitted | 已重新提交 | 否 |
| approved | 已通过 | 否 |
| rejected | 未通过 | 否 |
| archived | 已归档 | 否 |

### 6.2 保存与提交快照

建议区分草稿数据和提交快照。

- 草稿数据：教师可持续编辑。
- 提交快照：每次提交生成不可变版本。
- 审核意见绑定到提交快照或具体字段。
- 归档导出使用最终通过的提交快照。

### 6.3 字段级校验结果

建议保存校验结果，便于展示完成度。

字段：

- material_id
- module_key
- section_key
- field_key
- level：error / warning
- message
- updated_at

## 7. 分期实施建议

### 7.1 第一阶段：降低填报失败率

目标：教师能清楚知道自己要做什么、哪些没填、是否已保存。

建议实现：

- 教师端工作台。
- 填报页完成度和错误提示。
- 自动保存状态。
- 提交前完整性检查。
- 退回意见列表和定位。

### 7.2 第二阶段：提升填报效率

目标：减少重复录入和附件返工。

建议实现：

- 基本信息复用。
- 表格型内容行内编辑、复制行、Excel 粘贴。
- 附件中心和字段级关联。
- 常用附件复用。

### 7.3 第三阶段：提升最终材料质量

目标：教师提交前即可确认最终申报表效果。

建议实现：

- A4 打印预览。
- PDF 预览和下载。
- 预览异常定位。
- 提交快照和归档下载。

### 7.4 第四阶段：提升服务体验

目标：减少教师咨询成本和错过节点风险。

建议实现：

- 多渠道通知。
- 字段级填报说明。
- 常见问题与示例。
- 移动端轻量处理。

## 8. 优先级清单

| 优先级 | 需求 | 价值 |
| --- | --- | --- |
| P0 | 教师端工作台 | 让教师清楚知道待办和状态 |
| P0 | 完整性检查 | 降低提交失败和退回率 |
| P0 | 自动保存 | 避免长表单数据丢失 |
| P0 | 基本信息复用 | 减少重复录入 |
| P1 | 表格型高效录入 | 提升大量成果填报效率 |
| P1 | 附件中心 | 降低材料缺失和关联混乱 |
| P1 | 打印预览 | 减少格式返工 |
| P1 | 退回意见定位 | 提升修改效率 |
| P2 | 填报说明和示例 | 降低咨询成本 |
| P2 | 多渠道通知 | 降低错过节点风险 |
| P2 | 移动端轻量体验 | 支持碎片化处理 |

## 9. 验收指标

建议用以下指标衡量教师端优化效果：

- 首次提交成功率。
- 平均填报耗时。
- 因必填缺失导致的退回数量。
- 因附件缺失或附件错误导致的退回数量。
- 教师端保存失败率。
- PDF 预览后返回修改次数。
- 截止前未提交人数。
- 教师咨询工单数量。

## 10. 结论

教师端优化的核心不是增加更多配置项，而是让教师少理解系统、多完成任务。优先建设工作台、完整性检查、自动保存、基本信息复用和退回意见定位，可以最快降低填报焦虑和管理员沟通成本；随后再补齐表格高效录入、附件中心和打印预览，才能真正支撑复杂申报材料的高质量提交。
